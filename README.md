# 幸运抽奖系统（微信扫码 · 多轮开奖）

现场活动抽奖系统：观众扫二维码经微信服务号授权进入奖池（**只需扫一次**），奖品多轮抽取，
**已中奖用户不可重复中奖**，大屏喜庆展示。针对**现场外网不稳定**做了专门设计：
**云签到 + 本地开奖**双节点架构，签到数据自动回流到现场本地，开奖全程不依赖外网，结果断网续传。

## 架构

```
手机(蜂窝网络) ──→ 云端节点(公网域名)          现场笔记本(本地节点) ←── 大屏/操作机(局域网)
                  微信OAuth签到、用户页           开奖引擎、大屏页、管理台
                  用户头像代理缓存到磁盘    ═══╗   ╔═══ 增量拉取用户+头像（数据回流到本地）
                  接收结果推送、供手机查询    ═══╝   ╚═══ 结果快照断网续传回云端
```

- **云端 = 签到数据唯一写入方；本地 = 开奖数据唯一写入方**，双向同步天然无冲突
- 防重复中奖由数据库硬保证：`winners.user_id` 全局 UNIQUE + 事务化抽取（连点/重试幂等）
- 断外网时：本地照常开奖（头像已落盘），结果进入离线队列，链路恢复自动回传，手机端补看结果

## 快速开始（单机彩排模式）

```bash
npm install
npm start            # 默认 ROLE=standalone + Mock 登录，端口 3000
```

- 用户页:  http://localhost:3000/  （Mock 模式下点"随机身份"即可签到）
- 大屏:    http://localhost:3000/screen.html （含开奖控制条，按 F 全屏）
- 管理台:  http://localhost:3000/admin.html （密钥默认 `change-me-admin-key`，来自 .env）
- 一键造演示数据（60 用户 + 3 轮次）: `node scripts/demo-seed.js`

彩排全流程：**管理台**建轮次/传奖品图 → **大屏页**控制条开奖（首次点按提示输入 ADMIN_KEY 授权，之后 `←/→` 切轮、`空格/回车` 一键 开始滚动→揭晓→下一轮）→ 需要修正时回管理台弃奖/补抽/回滚 → 清空中奖记录再来一遍。

> 职责分工：**大屏 = 开奖现场**（选轮、滚动、揭晓全在大屏页面操作）；**管理台 = 幕后**（奖品轮次配置、中奖记录管理、名单兜底、数据重置）。

### 领奖核对流程

1. 管理台顶栏「🎫 领奖查询码」→ 打印张贴在领奖台（指向 `云端/?claim=1`）
2. 用户扫码：自动登录（复用签到授权），页面直接显示**是否中奖**；中奖者额外显示**领奖凭证码**（如 `LD0K4`）
3. 工作人员在管理台中奖条 / 导出 CSV 中核对凭证码与姓名，一致即发奖
4. 凭证码由 winner id + COOKIE_SECRET 派生，稳定可复现、不可猜测

### 扫码填资料（签到第二页）

- 流程：扫码 → 微信授权 → **资料页**（姓名*、手机号*、部门选填）→ 提交进奖池
- 大屏/名单/导出**优先显示真实姓名**（无资料时回落微信昵称）；手机号进管理台名单与导出 CSV
- 管理台「活动设置 → 扫码需填资料」开关可关闭（关闭则授权后直接进奖池）
- 数据随签到同步回流本地（`users.real_name/phone/dept` 列，存量库自动迁移）

## 正式活动部署（云端 + 本地双节点）

### 1) 云端节点（公网服务器）

```bash
# .env
ROLE=cloud
PORT=3000
BASE_URL=https://draw.example.com        # 已备案域名 + HTTPS
PAIR_KEY=<随机长串>
ADMIN_KEY=<随机长串>
USE_MOCK=0
WECHAT_APP_ID=wx1234567890
WECHAT_APP_SECRET=<公众号后台获取>
```

用 pm2 常驻：`npm i -g pm2 && pm2 start server/index.js --name luckydraw-cloud`
（HTTPS 由 Nginx/Caddy 反代终止，证书需覆盖该域名）

### 2) 本地节点（现场笔记本）

```bash
# .env
ROLE=local
PORT=3000
CLOUD_URL=https://draw.example.com      # 云端 API 地址
CLOUD_PUBLIC_URL=https://draw.example.com
PAIR_KEY=<与云端一致>
ADMIN_KEY=<随机长串>
```

`pm2 start server/index.js --name luckydraw-local`（或直接 `npm start`）
投影仪浏览器开 `http://<笔记本IP>:3000/screen.html` 按 F 全屏；操作机开 `/admin.html`。

> 手机与云端之间走蜂窝网络即可；笔记本与现场外网之间断不断都**不影响开奖**。
> 建议：会前在云端 `/dev/seed?n=1` 冒烟（USE_MOCK=0 时需带 ADMIN_KEY），然后 reset all 清掉。

### 3) 网络兜底手段（按优先级）

1. 签到高峰在入场时段自然摊薄；每轮**开奖前本地自动强制拉取一次**迟到签到
2. 手机完全无信号的用户：管理台「参与名单」面板**补录/批量导入**（姓名,手机尾号），直接进本地奖池
3. 云端彻底不可用：本地独立完成整场活动，名单可从本地导出 CSV
4. 彩排后重置：管理台「清空中奖记录」保留签到，「清空全部」彻底重来

## 微信服务号配置（切真实模式清单）

1. **认证服务号** → 设置与开发 → 公众号设置 → 功能设置 → **网页授权域名** 填 `draw.example.com`
   - 按提示下载 `MP_verify_xxx.txt` 放到 `public/` 目录（文件名以公众号后台为准）
2. 设置与开发 → 基本配置 → **IP 白名单**加入云端服务器公网 IP（获取 access_token 用）
3. `.env` 填 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`，`USE_MOCK=0`，重启云端
4. 验证：手机扫码 → 出现微信授权页 → 同意后进入参与成功页
5. 昵称乱码/头像为空：本系统已内置昵称编码修复与头像本地缓存；如仍异常检查 IP 白名单

注意：网页授权域名必须**已备案 + HTTPS**，且不支持 IP/端口/内网地址——这正是需要云端节点的原因。

## 断网演练手册（活动前必做）

1. 双节点启动，云端签到若干用户，确认本地管理台「云端在线 · 已同步」、奖池人数增长
2. **停掉云端进程（模拟断外网）** → 管理台应显示「云端离线 · 结果排队续传中」
3. 本地照常「滚动 → 揭晓」开奖，大屏动画/名单正常（头像走本地缓存）
4. 重启云端 → 数秒内状态恢复「已同步」，手机端用户页可查到中奖结果
5. 演练完成后「清空中奖记录」

## 关键设计说明

| 关注点 | 方案 |
|---|---|
| 扫码一次 | 授权后 90 天 HMAC 签名 Cookie（HttpOnly），服务重启不掉线 |
| 不重复中奖 | `winners.user_id` 全局 UNIQUE；抽取 SQL `NOT IN (winners)` 单事务完成；弃奖者同样出局 |
| 签到并发 | `users.openid` UNIQUE + 幂等插入；SQLite WAL 读写不互阻，数百人峰值无压力 |
| 开奖幂等 | 轮次状态机 pending→drawn，重复请求返回既有结果 |
| 弱网（手机） | API 超时+指数退避+离线提示条；长轮询秒级收结果；Service Worker 壳缓存 |
| 弱网（现场） | 大屏/管理台全走局域网；头像提前落盘；结果离线队列续传 |
| 兜底 | 名单导入/补录（负数 id 本地用户，不与云端冲突）、CSV 导出、一键重置 |

## 目录结构

```
server/
  index.js            入口（按 ROLE 装配）
  db.js               SQLite（WAL）schema
  config.js           .env 解析
  lib/                签名 Cookie / 限流 / 头像缓存
  services/           draw(事务化抽奖) sync(回流+续传) wechat(OAuth适配) users state
  routes/             auth / api(用户) / screen(大屏) / admin / sync(云端侧)
public/               index(用户页) screen(大屏) admin(管理台) + sw.js
data/                 SQLite 库与头像缓存（运行时生成，勿提交）
```
